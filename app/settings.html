Search & Rescue operator guide

The workbench turns lost-person-behavior statistics and incident context into ranked probability-of-area search segments. It combines an Initial Planning Point, subject profile, scenarios, terrain, directional evidence and linear features.

Operational purpose: support trained SAR planning. The model does not replace incident command, field intelligence, agency procedures or professional judgment.

Start an incident

  1. Enter an incident name.
  2. Set the Initial Planning Point by coordinates or by selecting the map.
  3. Record the last-seen time.
  4. Add probability-weighted scenarios when more than one explanation is credible.

The IPP should represent the best-supported Last Known Point or Place Last Seen, not a convenient map center.

Build the subject profile

Select the subject category, environment and terrain. Review the matching source, sample size, percentile distances and fallback warnings. Placeholder records are explicitly marked and must not be treated as operational evidence.

Run the model

  1. Review or adjust model weights.
  2. Add trusted trails, roads, drainages or other linear features where appropriate.
  3. Enable terrain travel time and elevation bias only when the DEM and local conditions support those assumptions.
  4. Run the model and review warnings before interpreting the result.

Search segments and POD

Segments are ranked by Probability of Area. After a search assignment, enter the estimated Probability of Detection and apply the result. The workbench redistributes the remaining probability; it does not certify that a segment is clear.

Map tools and Living Atlas

Use native ArcGIS map controls for LayerList, Legend, BasemapGallery, Sketch, Measurement, Locate, CoordinateConversion, Search, Home and Print. Import and Export are supplemental file controls.

From Layers, load optional Living Atlas land cover, hydrography, weather, wildfire and hillshade. They start turned off. Enable only relevant layers and check source currency before acting.

ArcGIS and field operations

Saving requires an authorized ArcGIS organizational account and a configured OAuth application. Keep the hosted service and Web Map private or shared only with a restricted SAR group. Configure Field Maps forms and offline areas before field deployment.

Troubleshooting

The map is blank

Confirm network access to ArcGIS Online and refresh the page. Disable optional context layers if a high-demand live feed is slow.

Save is unavailable

Verify CONFIG.appId, the registered redirect URI, item sharing and edit privileges.

Living Atlas layers fail

Check the ArcGIS session, item entitlement, source sharing and live-feed status. Retry from the native Layers control.

The model reports missing statistics

Select another supported category/environment combination or load an authorized statistics CSV.

Safety and limitations

Decision support only. Outputs are estimates, not certainties. Validate against field reports, weather, access, hazards, jurisdictional guidance and current incident intelligence.
  • Do not publish sensitive subject or clue data.
  • Do not treat live feeds as monitored emergency notification systems.
  • Do not use synthetic or placeholder LPB records operationally.
  • Record model provenance and assumptions for each operational run.

Configuration settings

  • Apply draft for review: previews branding on this page without saving.
  • Save settings: stores validated browser-local defaults. Other open workbench tabs reload automatically.
  • Discard changes: reloads the last saved settings.
  • Reset to base defaults: loads the repository defaults after confirmation.
  • Export / Import template: transfers configuration as JSON for review and reuse.

Browser settings do not change ArcGIS service schemas, item sharing, OAuth registration or hosted data.
