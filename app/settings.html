Search & Rescue operator guide

The workbench turns lost-person-behavior statistics and incident context into ranked probability-of-area search segments. It combines an Initial Planning Point, subject profile, scenarios, terrain, directional evidence and linear features.

Operational purpose: support trained SAR planning. The model does not replace incident command, field intelligence, agency procedures or professional judgment.

Layout, sidebars and navigation

The shared header opens Planning, Operations, Incident Analysis, Reports, Settings and ArcGIS sign-in. On desktop, thin amber handles with small dotted grip indicators resize both sidebars and content sections. Planning supports its workflow and Assignment & Asset Design rails plus each workflow section; Operations supports its workflow rail, Operational Layers panel and content cards; Analysis supports its filter/details rail and every major dashboard row.

  • Focus a resize handle with Tab. Use Left Arrow or Right Arrow for sidebar width, and Up Arrow or Down Arrow for section height.
  • Hold Shift with an arrow for 50-pixel changes. Home selects the minimum and End the largest safe dimension.
  • Double-click a sidebar handle to restore its default width, or a section handle to fit its content. Saved dimensions return after reload.
  • In Analysis, use the arrow in Analysis filters to collapse or reopen the entire filter and incident-details rail. That collapsed state is also saved.

Resize handles disappear in stacked/mobile layouts so panels remain full-width. The three workspaces keep the map and primary actions ahead of secondary detail on small screens.

Planning

The Planning workspace has five left-side sections—Incident, Subject, Model, Segments and Survival—a central ArcGIS map, and the independent Assignment & Asset Design rail on the right. Use the header Reports selector for planning PDFs and the shared navigation to move to Operations or Analysis.

  1. Incident: name the incident, set the Initial Planning Point, record last-seen time and maintain probability-weighted scenarios.
  2. Subject: select the lost-person category and environment, review matched statistics, and capture only operationally necessary interview details.
  3. Model: review weights, terrain assumptions, interview cues and linear features before running the probability model.
  4. Segments: inspect ranked POA, estimated POD, applied POD and cumulative POS. The list and mapped polygons use the complete model result even when the visible table is abbreviated.
  5. Survival: review the category curve as an urgency input, not a stopping rule.
  6. Assignment & Asset Design: prepare assignment geometry and tasks separately from named assets. Placing an asset never creates an assignment.

Small export buttons in the upper-right of supported statistics, survival, scenario, segment, assignment and asset sections provide CSV, JSON and spatial Shapefile output when geometry exists. Use the lower-left 2D Map / 3D Terrain control to compare operational layers with ArcGIS World Elevation; perform edits in 2D.

Start an incident

  1. Enter an incident name.
  2. Set the Initial Planning Point by coordinates or by selecting the map.
  3. Record the last-seen time.
  4. Add probability-weighted scenarios when more than one explanation is credible.

The IPP should represent the best-supported Last Known Point or Place Last Seen, not a convenient map center.

Build the subject profile

Select the subject category, environment and terrain. Review the matching source, sample size, percentile distances and fallback warnings. Placeholder records are explicitly marked and must not be treated as operational evidence.

Lost person interview

The structured interview follows the operational topics in the Nicolet Search Team Lost Person Interview Report: immediate planning information, health and vulnerability, clothing and equipment, outdoor experience, trip plan, prior actions and behavior.

  1. Capture immediate direction, intent, condition and overdue time first.
  2. Record health, medication and behavior information only when operationally necessary.
  3. Use Apply supported cues to planning to transfer a reported true bearing, trail tendency or continued-movement cue. Review every resulting change.
  4. Export the interview only to an agency-approved protected location.
  5. Leave Include interview fields in ModelRun provenance off unless policy permits storing sensitive interview information in ArcGIS Online.
Privacy: the interview can contain medical, behavioral, family and contact information. Minimize collection, restrict sharing and follow agency retention policy.

Run the model

  1. Review or adjust model weights.
  2. Add trusted trails, roads, drainages or other linear features where appropriate.
  3. Enable terrain travel time and elevation bias only when the DEM and local conditions support those assumptions.
  4. Run the model and review warnings before interpreting the result.

Search segments and POD

Segments are ranked by Probability of Area. After a search assignment, enter the estimated Probability of Detection and apply the result. The workbench redistributes the remaining probability; it does not certify that a segment is clear.

Shared map tools and context

Planning, Operations and Analysis use native ArcGIS controls for layers, legend, basemaps, bookmarks, search, home, scale and other page-appropriate tools. Every interactive map shows UTM easting labels along the bottom edge and UTM northing labels along the right edge; map-bearing reports carry the same UTM scales. Search zooms to a selected address or place. Planning and Operations bookmarks are stored separately in this browser; they are not synchronized or included automatically in exports.

USGS Topo is available as a shared context layer in 2D maps, 3D terrain views, Field Maps and report maps. Use the lower-left 2D Map / 3D Terrain control to view current operational layers over hybrid imagery, USGS Topo and ArcGIS World Elevation with shadows and ambient occlusion. Return to 2D before editing.

The saved coordinate format controls Planning and Operations readouts and report-grid labels. Decimal Degrees, DDM and DMS are local. UTM, USNG and MGRS use ArcGIS CoordinateFormatter and report honestly when unavailable.

Optional Living Atlas land cover, hydrography, weather, wildfire and hillshade start turned off. Enable only relevant sources and verify currency. FCC-sourced tower-radius circles are communications-planning estimates, not carrier-provided RF coverage; they omit terrain, sectors, frequency, power, capacity, foliage, buildings and outages.

Operations

The Operations workspace is the common operating picture for mapped objects, assignments, field resources and reports. The left rail contains Edit Map, Assignments, Resources and Reports; the center is the operational map; the collapsible Operational Layers panel controls visibility and feature zoom.

  1. Enter or discover the incident ID, choose an operational period, then load local or ArcGIS records.
  2. Use Edit Map to draw and maintain areas, segments, PLS/IPP, clues, pings, hazards, routes, tracks, facilities and assets.
  3. Use Assignments to link a team and task to a segment, then record status, team debrief POD, search-again decision and notes.
  4. Use Resources for JSON, GeoJSON, GPX, KML and assignment CSV exchange and the Field Maps companion workflow.
  5. Use Reports for map products, assignment documents and the Missing Person Flyer.

The operational feature and assignment lists have upper-right CSV, JSON and Shapefile export controls. The lower-left 2D/3D control carries current operational layers into terrain context; editing stays in 2D. Browser-local edits remain unsynced until Sync unsaved succeeds.

SAR Operations map editing

Open SAR Operations from the Planning or Settings header. Use the header to find incident numbers across the service or only within the current map extent, choose an operational period, and apply the filters. You can also enter the same incident ID used in Planning, then load ArcGIS to bring ranked search segments into the operational workspace.

  1. Choose Area, Segment, Point Last Seen, Clue or Cell Ping.
  2. Draw with the native ArcGIS sketch workflow. Snapping is enabled by default.
  3. Select the object on the map, in the left object list or in the right Operational Layers panel.
  4. Review its identifier, status, priority, folder, operational period and notes.
  5. Use Save properties, Edit geometry, Duplicate or Done. Unsynced edits remain browser-local until Sync unsaved succeeds.
Cell pings: radius, bearing and sector width are investigative inputs, not verified device locations or RF propagation.

Reports and Missing Person Flyer

Planning’s Reports selector includes a Missing Person Flyer. Operations provides the same action from its Reports tab and uses the latest browser-saved Planning subject snapshot. If Operations reports that no snapshot exists, open Planning and enter the incident and subject information first.

  1. Review the prefilled name, age, sex or gender, clothing, last-seen date/time and selected subject photo.
  2. Enter or correct date of birth, race, eyes, hair, height, weight, identifying characteristics and all public contact details.
  3. Choose one uploaded Planning photograph when several exist. A no-photo flyer uses an explicit placeholder.
  4. Generate the one-page US Letter portrait PDF, inspect it, and obtain operational/public-release approval before posting.

Flyer/contact drafts are stored locally per incident when practical. Reset draft returns fields to current Planning values; Cancel closes without changing analytical subject inputs. The draft stores only a photo index, not another image copy. Avoid entering information that is not approved for public release.

Analysis

The Analysis workspace uses a command-center dashboard: filter-linked KPIs across the top, Incident Hotspots and the weekday/hour heat chart in the primary row, supporting trend and outcome charts below, and a right-side Analysis filters / Incident details rail. Use the rail arrow to collapse it and give charts more room.

  1. Choose an incident scope or All incidents, optional start/end dates, status, subject category and operational period, then select Apply filters.
  2. Select an incident in Incident details to focus the map and all metrics on that incident. Select the same incident again to return to the map extent used before zooming. Use Reset to clear form filters and the time-cell selection.
  3. Use the lower-left selector to choose Incidents, Located heat or Combined. The ArcGIS map controls provide location search, Home, Zoom, Layers, Legend, Basemaps, browser-local Bookmarks and Measurement; use the 2D/3D control for terrain context.
  4. Click a weekday/hour heat-chart cell to cross-filter the map, KPIs, incident details, every other chart and all exports. Select additional cells for an inclusive multi-selection; click a selected cell again or choose Clear time filter to remove it.
  5. Use the small export button in the upper-right of each supported chart/list for CSV, JSON or zipped Shapefile. Exports use the full active filtered dataset rather than only visible rows.
  6. Select Reload data to refresh browser and hosted sources and review the displayed source/freshness message.

The page merges browser-saved sar.operations.* workspaces with paginated read-only ArcGIS FeatureLayer queries for Incident, KeyPoints, Clue and Task. Duplicate incident IDs are combined. If hosted ArcGIS data cannot be read, the page clearly switches to browser-only analysis.

Metric definitions: Located rate counts incidents with a Find point. Time until located uses last_seen to the earliest non-negative Find time. Timeline charts use adaptive UTC day, week or month buckets. The trend line is cumulative incident count. Month/day and weekday/hour charts use valid UTC last_seen timestamps. Straight-line displacement uses IPP (or Incident point) to Find and is not travel distance. Located heat represents observations, not unique incidents or probability.

Analysis can reveal sensitive subject locations, clues, assignments and responder activity. Use an approved device, restrict sharing, avoid public screenshots/exports, and reconcile every metric with current incident-command records. Freshness is load time, not proof of field-data currency.

Assignments and debrief

Planning can prepare a segment, team, task description, operational period, priority and initial status in Assignment & Asset Design. Operations owns the field workflow and detailed assignment record: task type, transportation, expected hours, radio, team size, prepared-by information, prior effort and notes.

When field work returns, record assignment status, responsive/unresponsive/clue POD inputs, debrief POD, debrief notes and whether the area should be searched again. Completed work requires both POD and a search-again decision. Print assignment documents from Reports and refresh Planning to see operational outcomes.

Statuses represent workflow state, not field safety or completion certification. Confirm deployment, communications and debrief details with incident command.

Operational layers, resources and Field Maps

The right-side Operational Layers panel controls visibility and provides layer-level and feature-level zoom. Selecting a named feature zooms to it, opens its safe Arcade popup and loads it into the editing form. Popups show type, status, priority, operational period, folder, geometry measurements, notes and synchronization state.

Use Resources for operations JSON, GeoJSON, GPX, KML and assignment CSV exchange. The Field Maps companion workflow creates or refreshes the shared mobile Web Map so teams can review assignments, navigate, capture clues and photos, and collect progress lines. Prepare offline areas and forms before deployment; after field collection, return to Operations and refresh/synchronize before analysis or reporting.

ArcGIS and field operations

Saving requires an authorized ArcGIS organizational account and a configured OAuth application. Keep the hosted service and Web Map private or shared only with a restricted SAR group. Configure Field Maps forms and offline areas before field deployment.

Troubleshooting

The map is blank

Confirm network access to ArcGIS Online and refresh the page. Disable optional context layers if a high-demand live feed is slow.

Save is unavailable

Verify CONFIG.appId, the registered redirect URI, item sharing and edit privileges.

Living Atlas layers fail

Check the ArcGIS session, item entitlement, source sharing and live-feed status. Retry from the native Layers control.

The model reports missing statistics

Select another supported category/environment combination or load an authorized statistics CSV.

Safety and limitations

Decision support only. Outputs are estimates, not certainties. Validate against field reports, weather, access, hazards, jurisdictional guidance and current incident intelligence.
  • Do not publish sensitive subject or clue data.
  • Do not treat live feeds as monitored emergency notification systems.
  • Do not use synthetic or placeholder LPB records operationally.
  • Record model provenance and assumptions for each operational run.

Configuration settings

  • Apply draft for review: previews branding on this page without saving.
  • Save settings: stores validated browser-local defaults. Other open workbench tabs reload automatically.
  • Discard changes: reloads the last saved settings.
  • Reset to base defaults: loads the repository defaults after confirmation.
  • Export / Import template: transfers configuration as JSON for review and reuse.
  • Operational period duration: defaults to 12 hours and can be configured from 1 to 72 hours; Operations uses it in header period choices.
  • Coordinate display format: controls Planning and Operations coordinate readouts and the labels on report geographic reference grids. Decimal Degrees, Degrees Decimal Minutes and Degrees Minutes Seconds are formatted locally. UTM, USNG and MGRS use ArcGIS Maps SDK CoordinateFormatter; if it cannot load, the app says the requested notation is unavailable rather than relabeling decimal degrees.
  • Theme preview: the Configuration tab includes a responsive live specimen that follows branding draft changes.
  • Interface theme: Planning, Operations and Settings use the same Calcite dark theme with amber primary actions, amber outlined secondary actions and red danger actions.

Browser settings do not change ArcGIS service schemas, item sharing, OAuth registration or hosted data.
